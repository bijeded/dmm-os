# Migrations run with foreign keys off, checked before commit

`migrar` in `src/main/db/index.ts` applies pending migrations itself instead of calling drizzle's `migrate`. It reads the same migration files and records them in the same `__drizzle_migrations` table, so drizzle-kit stays the source of migrations and a database migrated either way looks the same. The difference is that it turns foreign keys off around the transaction. SQLite ignores `PRAGMA foreign_keys` inside a transaction, and drizzle's migrator runs everything inside one, so a migration that rebuilds a referenced table (as adding `retenciones` and its check to `ingresos` did) would cascade-delete or refuse to drop under its references. With keys off, `foreign_key_check` runs before commit, and any broken reference rolls every pending migration back. We rejected adding `PRAGMA foreign_keys=OFF` to the generated SQL, which does nothing inside the transaction, and splitting rebuilds into hand-ordered steps per migration, which every future rebuild would have to repeat. The cost is that we own the migrator: if drizzle changes how it records migrations, `migrar` and `lastApplied` must follow.
